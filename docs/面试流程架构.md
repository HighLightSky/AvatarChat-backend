## 关于架构：

- **业务后端**：处理面试配置、面试流程管理、数据持久化、用户权限验证等核心业务
- **数字人后端**：基于OpenAvatarChat框架，负责实时音视频对话、面试执行等高性能要求业务
- **MySQL**
- **OSS对象存储**：视频、知识库源文件、向量db
- **业务后端和数字人后端利用Redis做状态共享**

## 关于面试：

我希望能将整个面试流程分割成小块，用户能够自由组合：

**面试源数据配置**：`岗位+知识库数据+题库+简历数据`自由组合（可以在面试开始前由用户组合，也可以从社区获取已有的组合）

 - 岗位可以由用户创建，也可以从社区中获取
 - 知识库只能从社区中选取
 - 题库可以由用户创建，也可以从社区中获取
 - 一名用户可以同时拥有多份简历，任选一份进行面试
 - 面试的企业（企业文化等）

**面试流程配置**：以下流程 `顺序、时长、占比` 可自由组合

 - 面试前寒暄（固定流程不可变）
 - 技术面试【灵活度低，考察基本知识】（按照知识库+题库提问，对候选人上下文参考少，对简历参考少）
 - 简历面试【灵活度高，项目深挖】（知识库+题库参考少，对候选人上下文参考较多，主要参考简历）
 - 素质面试【手写代码/算法或系统设计】（不涉及上下文，使用线上OJ/输入框，直接评判）
 - 经验面试【沟通能力、团队协作、解决问题的方式、职业规划等】（基本不参考知识库+题库，对候选人上下文参考较多，对简历参考少）
 - 面试结束，感谢参与（固定流程不可变）

**面试过程中：**

- 后端视频完整录制
- 数字人实时对话
- 状态实时分析，分析结果作为上下文传入
- 【可选】根据面试者回答异步调用RAG检索



## 关于双系统通信-按面试阶段：

#### 阶段1：面试准备

- 【业务前端】用户选择面试配置
- 【业务后端】将配置保存至数据库
- 【业务后端】生成面试id，并确保数据库中保存状态，初始化OSS存储（数据库存储OSS路径）
- 【业务前端】通过面试id跳转连接【数字人前端】 
- 【数字人前端】向【数字人后端】发送初始化指令
- 【数字人后端】根据id读取数据库配置
- 【数字人后端】根据配置信息加载：岗位数据检索、知识库数据检索并浓缩、题库检索并浓缩、简历要点分析。内容嵌入初始提示词
- 【数字人后端】初始化数字人会话引擎
- 【Redis状态共享】更新状态数据

> 业务后端通过Redis状态共享得到面试进行中的数据

#### 阶段2：面试进行中，实时状态同步

- 【数字人后端】触发状态更新时（checkpoint）
  - 【Redis状态共享】更新状态
  - 将面试实录数据checkpoint同步到OSS
  - 向【业务后端】请求更新数据库状态（比如已经进行到哪一步了）

> 确保当意外连接中断时，可以从断连的上一个checkpoint恢复数据

#### 阶段3：面试结束，保存面试实录供分析

关闭（点击“结束面试” or 数字人发出结束指令 or 意外断开连接），触发面试实录保存

- 【数字人后端】执行结束流程：
  - 停止录制视频流，完成视频文件编码
  - 生成最终转录文件（合并所有checkpoint转录）
  - 将所有文件上传至OSS，获取永久URL
  - 更新Redis状态：status = "processing_final"
  - 向【业务后端】请求更新数据库状态（面试结束）
- 【业务后端】接收消息，更新数据库
- 【数字人后端】关闭数字人会话引擎，释放资源
- 【数字人前端】自动跳转回【业务前端】结果页面

#### 阶段4：使用评估服务生成最终评估报告



## 相关API

业务前端跳转到数字人前端的url，跳转以开始面试。

```
GET /interview/id
```

数字人前端会向数字人后端发送请求。

数字人后端接收到请求之后，向业务后端发送面试配置查询请求，获取该场面试的全部配置信息（源数据、流程等）

```
GET /api/interviews/{interview_id}/config
```

根据获取到的配置准备数据。

准备完成，开始面试。

```
POST /api/interviews/{interview_id}/start
```

面试过程中，创建检查点数据。（在完成一个检查点时调用，将关键状态同步至业务后端数据库。）

```
POST /api/interviews/{interview_id}/checkpoint
```

面试结束，更新面试状态。

```
POST /api/interviews/{interview_id}/complete
```

> 凡是对关系数据库的操作必须通过业务后端。使设计符合单一职责原则。



## 数据存储方式

#### 1 面试状态表

- 基础信息跟随当前业务后端的配置，外键关联
- **配置信息JSON具体包括哪些键，还需要另外设计**
- 媒体文件存储位置保存方式：以checkpoint为基本单位保存，每一个checkpoint包含【一段视频+一段音频+一段JSON（包含语音转录和实时分析】
- 加载面试记录，需要将检查点按照时间戳拼接
- **评估结果需要另外设计，简易外键报告id**

```SQL
-- 面试记录状态
CREATE TABLE interview_records (
    id VARCHAR(32) PRIMARY KEY COMMENT '面试ID',
    acatar_id VARCHAR(50) COMMENT '数字人会话实例ID',
    
    -- 基础信息（外键关联）
    user_id VARCHAR(32) NOT NULL COMMENT '用户ID',
    position_id VARCHAR(32) COMMENT '岗位ID',
    resume_id VARCHAR(32) COMMENT '简历ID',
    
    -- 配置信息（JSON格式）
    source_config JSON COMMENT '源数据配置：{position_id, knowledge_base_ids[], question_bank_ids[], resume_id, company_culture_id}',
    process_config JSON COMMENT '流程配置：{stages: [{type, duration, weight, order}], total_duration}',
    
    -- 状态流转
    status ENUM(
        'draft',           -- 已创建未开始
        'initializing',    -- 初始化中
        'ready',           -- 就绪，等待开始
        'in_progress',     -- 进行中
        'paused',          -- 已暂停
        'completed',       -- 正常完成
        'terminated',      -- 异常终止
        'processing',      -- 后处理中
        'archived'         -- 已归档
    ) DEFAULT 'draft' NOT NULL,
    
    -- 时间戳
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    started_at DATETIME COMMENT '面试开始时间',
    completed_at DATETIME COMMENT '面试完成时间',
    archived_at DATETIME COMMENT '归档时间',
    
    -- 进度信息
    current_stage VARCHAR(50) COMMENT '当前阶段',
    stage_started_at DATETIME COMMENT '当前阶段开始时间',
    
    -- 媒体文件存储位置
    oss_base_path VARCHAR(500) COMMENT 'OSS基础路径: interviews/{interview_id}/',
    
    -- 检查点信息
    checkpoint_count INT DEFAULT 0 COMMENT '检查点数量',
    last_checkpoint_at DATETIME COMMENT '最后检查点时间',
    
    -- 评估结果
    report_id VARCHAR(32) COMMENT '评估报告ID（可关联评估报告表）',

    -- 常用索引
    KEY idx_user_id (user_id),
    KEY idx_status (status),
    KEY idx_current_stage (current_stage),
    KEY idx_created_at (created_at),
    KEY idx_report_id (report_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='面试记录表';
```



#### 2 检查点元数据表

- 每一段checkpoint包括一轮完整对话（一问一回答）
- 数据库只保存元数据，具体数据【一段视频+一段音频+一段JSON（包含语音转录和实时分析】存在OSS

```SQL
CREATE TABLE interview_checkpoints (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    interview_id VARCHAR(32) NOT NULL COMMENT '面试ID',
    checkpoint_id VARCHAR(32) NOT NULL COMMENT '检查点序号',
    
    -- 状态信息
    current_stage VARCHAR(50) NOT NULL COMMENT '当前阶段',
    stage_progress INT NOT NULL COMMENT '阶段进度',
    total_progress INT NOT NULL COMMENT '总进度',
    
    -- 评估数据
    realtime_scores JSON COMMENT '本轮对话评分',
    rag_context JSON COMMENT 'RAG检索上下文（如果本轮对话调用RAG）',
    
    -- 系统状态
    begin_timestamp BIGINT COMMENT '开始时间戳',
    end_timestamp BIGINT COMMENT '结束时间戳',
    
    -- 存储位置
    oss_path VARCHAR(500) COMMENT '检查点OSS存储路径',
    
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,

    -- 唯一约束与索引
    UNIQUE KEY uk_interview_checkpoint (interview_id, checkpoint_id),
    KEY idx_current_stage (current_stage),
    KEY idx_created_at (created_at),

    CONSTRAINT fk_checkpoint_interview
        FOREIGN KEY (interview_id) REFERENCES interview_records(id)
        ON DELETE CASCADE
        ON UPDATE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='面试检查点表';
```
