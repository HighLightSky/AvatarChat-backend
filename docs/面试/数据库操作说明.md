# 面试数据库操作说明

本文档用于说明 interview 模式下数据库相关操作，包括：

1. 建表 SQL（与《面试流程架构》保持一致）
2. 独立 SQL 控制模块的使用方式
3. 使用 LLM 快速生成并写入模拟数据
4. 主 YAML + .env 配置约定

---

## 1. 数据表结构

已在 `docs/面试流程架构.md` 中完善两张核心表：

- `interview_records`
- `interview_checkpoints`

建议先执行文档中的建表 SQL（MySQL 版本），生产环境按业务后端统一迁移管理。

## 2. 独立 SQL 控制模块

新增模块：`src/service/interview_db/sql_controller.py`

核心能力：

- 表初始化：`init_tables()`（MySQL 版本）
- interview_records CRUD：
  - `create_interview_record()`
  - `get_interview_record()`
  - `list_interview_records()`
  - `update_interview_record()`
  - `delete_interview_record()`
- interview_checkpoints CRUD：
  - `create_checkpoint()`
  - `list_checkpoints()`
  - `update_checkpoint()`
  - `delete_checkpoint()`

### 2.1 最小使用示例

```python
from service.interview_db.sql_controller import InterviewSQLController

controller = InterviewSQLController(
    host="127.0.0.1",
    port=3306,
    user="root",
    password="your_password",
    database="open_avatar_chat",
)
controller.init_tables()

controller.create_interview_record({
    "id": "int_demo_001",
    "acatar_id": "avatar_demo",
    "user_id": "user_001",
    "position_id": "position_001",
    "resume_id": "resume_001",
    "source_config": {"position_id": "position_001"},
    "process_config": {"stages": []},
    "status": "in_progress",
    "current_stage": "technical",
    "oss_base_path": "interviews/int_demo_001/",
    "report_id": None,
})

controller.create_checkpoint({
    "interview_id": "int_demo_001",
    "checkpoint_id": "cp_001",
    "current_stage": "technical",
    "stage_progress": 1,
    "total_progress": 1,
    "realtime_scores": {"clarity": 4.5},
    "rag_context": {"source": "kb"},
    "begin_timestamp": 1739990000000,
    "end_timestamp": 1739990060000,
    "oss_path": "interviews/int_demo_001/checkpoints/cp_001.json",
})
```

## 3. LLM 模拟数据工具

新增工具：`src/utils/llm_mock_data_tool.py`

功能：

- 优先调用 LLM（阿里云百炼 OpenAI 兼容接口）生成结构化 interview 模拟数据
- 自动写入 MySQL（通过 SQL 控制模块）
- LLM 失败时自动回退到本地规则生成，保证可用性

### 3.1 运行方式

在项目根目录执行（确保 Python 能找到 `src` 包路径）：

```bash
python src/utils/llm_mock_data_tool.py --count 10 --checkpoint-per-interview 5
```

可选参数：

- `--config`：主配置 YAML 路径（默认 `config/chat_with_interview.yaml`）
- `--env`：Dynaconf 环境名（默认 `default`）
- `--mysql-host`：MySQL 主机（可选，覆盖 YAML/.env）
- `--mysql-port`：MySQL 端口（可选，覆盖 YAML/.env）
- `--mysql-user`：MySQL 用户（可选，覆盖 YAML/.env）
- `--mysql-password`：MySQL 密码（可选，覆盖 YAML/.env）
- `--mysql-database`：MySQL 数据库名（可选，覆盖 YAML/.env）
- `--mysql-charset`：MySQL 字符集（可选，覆盖 YAML/.env）
- `--count`：面试记录数量
- `--checkpoint-per-interview`：每条面试记录生成的 checkpoint 数
- `--model-name`：用于生成模拟数据的模型名（默认 `qwen-plus`）
- `--api-key` / `--api-url`：LLM 连接配置（默认读取环境变量）

### 3.2 独立建表工具（使用完善后的 SQL）

新增工具：`src/utils/create_interview_tables.py`

作用：直接执行 `InterviewSQLController` 内维护的完善版 MySQL 建表 SQL，创建：

- `interview_records`
- `interview_checkpoints`

示例：

```bash
python src/utils/create_interview_tables.py
```

### 3.3 环境变量建议

- `INTERVIEW_LLM_API_KEY`
- `INTERVIEW_LLM_API_URL`

MySQL 相关：

- `INTERVIEW_DB_HOST`
- `INTERVIEW_DB_PORT`
- `INTERVIEW_DB_USER`
- `INTERVIEW_DB_PASSWORD`
- `INTERVIEW_DB_NAME`
- `INTERVIEW_DB_CHARSET`

若未设置 Key，工具会自动使用本地兜底数据生成逻辑。

## 4. 主 YAML + .env 配置约定

主配置文件 `config/chat_with_interview.yaml` 中已新增：

```yaml
chat_engine:
  handler_configs:
    LLMInterviewOpenAICompatible:
      mysql:
        host: null
        port: null
        user: null
        password: null
        database: null
        charset: null
```

实际读取优先级：

1. CLI 显式参数
2. 主 YAML 的 `mysql` 配置段
3. `.env`（`INTERVIEW_DB_*`）
4. 代码默认值

推荐在项目根目录维护 `.env`：

```env
INTERVIEW_DB_HOST=127.0.0.1
INTERVIEW_DB_PORT=3306
INTERVIEW_DB_USER=root
INTERVIEW_DB_PASSWORD=your_password
INTERVIEW_DB_NAME=open_avatar_chat
INTERVIEW_DB_CHARSET=utf8mb4

INTERVIEW_LLM_API_KEY=your_llm_api_key
INTERVIEW_LLM_API_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

## 5. 与 interview 会话流程的关系

- `interview_records` 保存面试主状态
- `interview_checkpoints` 保存每轮 checkpoint 元数据
- 会话中的 checkpoint（LLM handler 内存态）可按阶段异步落盘/入库

建议在业务后端新增 API：

- `POST /api/interviews/{id}/checkpoint` → 调用 `create_checkpoint`
- `POST /api/interviews/{id}/complete` → 更新 `interview_records.status/report_id`

以实现“实时状态同步 + 最终归档”。
