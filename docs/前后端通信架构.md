# OpenAvatarChat 前后端通信架构

## 概述

OpenAvatarChat 采用 **WebRTC + FastAPI** 的混合架构实现前后端实时通信，支持音视频流的双向传输。

## 技术栈

### 后端
- **FastAPI**: HTTP API 服务器
- **Gradio**: Web UI 框架（可选）
- **aiortc**: Python WebRTC 实现
- **fastrtc**: WebRTC 流处理封装库（第三方）
- **Uvicorn**: ASGI 服务器

### 前端
- **Vue 3**: 前端框架
- **TypeScript**: 类型安全
- **Ant Design Vue**: UI 组件库
- **WebRTC API**: 浏览器原生 WebRTC
- **Vite**: 构建工具

## 通信流程详解

### 1. 应用启动流程

```python
# demo.py
def main():
    # 1. 创建 FastAPI 应用
    demo_app = FastAPI()
    
    # 2. 创建 Gradio UI（可选）
    gradio_block = gr.Blocks()
    
    # 3. 初始化 ChatEngine
    chat_engine = ChatEngine()
    chat_engine.initialize(engine_config, app=demo_app, ui=gradio_block)
    
    # 4. ClientHandlerRtc 在初始化时会：
    #    - 挂载 WebRTC 端点到 FastAPI
    #    - 注册 HTTP API 路由
    #    - 挂载前端静态文件
    
    # 5. 启动 Uvicorn 服务器
    uvicorn.run(demo_app, host="0.0.0.0", port=8282)
```

### 2. ClientHandlerRtc 的设置

```python
# client_handler_rtc.py
class ClientHandlerRtc(ClientHandlerBase):
    
    def on_setup_app(self, app: FastAPI, ui, parent_block):
        """在应用启动时设置 WebRTC 和 HTTP 接口"""
        
        # 1. 创建 WebRTC Stream 对象
        webrtc = Stream(
            modality="audio-video",      # 音视频模式
            mode="send-receive",         # 双向传输
            time_limit=900,              # 会话超时时间
            rtc_configuration=turn_config,  # TURN 服务器配置
            handler=self.rtc_streamer_factory,  # 流处理器工厂
            concurrency_limit=5          # 并发限制
        )
        
        # 2. 挂载 WebRTC 端点到 FastAPI
        webrtc.mount(app)  # 自动创建 /webrtc/offer 路由
        
        # 3. 注册配置 API
        @app.get('/openavatarchat/initconfig')
        async def init_config():
            return {
                "avatar_config": {...},
                "rtc_configuration": turn_config
            }
        
        # 4. 挂载前端静态文件
        frontend_path = Path('src/handlers/client/rtc_client/frontend/dist')
        app.mount('/ui', StaticFiles(directory=frontend_path))
        app.add_route('/', RedirectResponse(url='/ui/index.html'))
```

### 4. 音视频数据流处理

#### 4.1 客户端到服务器（上行）

```
麦克风/摄像头
    ↓
WebRTC PeerConnection (前端)
    ↓ (RTP 包)
aiortc (后端)
    ↓
RtcClientSessionDelegate.put_data()
    ↓
ChatData (MIC_AUDIO / CAMERA_VIDEO)
    ↓
Handler Pipeline:
    ├─ VAD Handler (检测人声)
    ├─ ASR Handler (语音转文字)
    ├─ LLM Handler (生成回复)
    ├─ TTS Handler (文字转语音)
    └─ Avatar Handler (生成表情动作)
```

#### 4.2 服务器到客户端（下行）

```
Avatar Handler (渲染视频帧)
    ↓
TTS Handler (生成音频)
    ↓
RtcClientSessionDelegate.get_data()
    ↓
aiortc (编码为 RTP)
    ↓ (RTP 包)
WebRTC PeerConnection (前端)
    ↓
<video> / <audio> 元素播放
```

### 5. 会话管理

```python
# 会话创建流程
class ClientHandlerDelegate:
    
    def start_session(self, session_id: str, **kwargs):
        """当 WebRTC 连接建立时创建会话"""
        
        # 1. 创建会话信息
        session_info = SessionInfoData(session_id=session_id)
        
        # 2. 通过 ChatEngine 创建会话
        session, handler_env = engine.create_client_session(
            session_info, 
            client_handler
        )
        
        # 3. 启动会话（初始化所有 Handlers）
        session.start()
        
        # 4. 创建会话代理（用于数据传输）
        session_delegate = RtcClientSessionDelegate()
        
        # 5. 设置数据通道
        handler.on_setup_session_delegate(
            session_context, 
            handler_context, 
            session_delegate
        )
        
        return session_delegate
```

### 6. 数据传输接口

```python
class RtcClientSessionDelegate(ClientSessionDelegate):
    """会话代理，负责前后端数据交换"""
    
    async def get_data(self, modality: EngineChannelType, timeout=0.1):
        """从 Handler Pipeline 获取数据发送给客户端"""
        # 从输出队列获取处理后的音视频数据
        data = await self.output_queue.get(timeout=timeout)
        return data
    
    def put_data(self, modality: EngineChannelType, data, timestamp=None):
        """接收客户端数据并发送到 Handler Pipeline"""
        # 将客户端音视频数据放入输入队列
        chat_data = ChatData(type=modality, data=data, timestamp=timestamp)
        self.input_queue.put(chat_data)
    
    def emit_signal(self, signal: ChatSignal):
        """发送控制信号（如开始/停止录音）"""
        self.signal_queue.put(signal)
```

## HTTP API 端点

### 1. 静态资源
- `GET /` - 重定向到前端应用
- `GET /ui/*` - 前端静态文件（HTML, JS, CSS）

### 2. 配置 API
- `GET /openavatarchat/initconfig` - 获取初始化配置
  ```json
  {
    "avatar_config": {
      "type": "lam",
      "model_path": "..."
    },
    "rtc_configuration": {
      "iceServers": [
        {
          "urls": "turn:server.com:3478",
          "username": "user",
          "credential": "pass"
        }
      ]
    }
  }
  ```

### 3. WebRTC 信令
- `POST /webrtc/offer` - WebRTC Offer/Answer 交换
  - 请求体：`{ type: "offer", sdp: "...", webrtc_id: "..." }`
  - 响应：`{ type: "answer", sdp: "..." }`

### 4. Gradio UI（可选）
- `GET /gradio` - Gradio Web 界面

## TURN 服务器配置

WebRTC 在 NAT 环境下需要 TURN 服务器中继流量：

```yaml
# config/chat_with_lam.yaml
chat_engine:
  turn_config:
    provider: "twilio"  # 或 "coturn"
    username: "your_username"
    credential: "your_password"
    urls:
      - "turn:turn.server.com:3478"
```

支持的 TURN 提供商：
- **Twilio**: 商业服务，稳定可靠
- **Coturn**: 开源自建方案
- **自定义**: 任何兼容 TURN 协议的服务器

## 数据格式

### ChatData 结构
```python
class ChatData:
    type: ChatDataType           # MIC_AUDIO, CAMERA_VIDEO, etc.
    data: DataBundle            # 实际数据（numpy 数组）
    timestamp: Tuple[int, int]  # (样本索引, 采样率)
    metadata: Dict              # 元数据
```

### 音频格式
- **采样率**: 16000 Hz（可配置）
- **通道数**: 1（单声道）
- **编码**: PCM Float32 (内部) / Opus (传输)

### 视频格式
- **分辨率**: 可配置（默认 512x512）
- **帧率**: 25 FPS（可配置）
- **编码**: H.264 (传输)

## 优势

1. **实时性**: WebRTC 提供低延迟音视频传输（< 100ms）
2. **双向通信**: 同时支持音视频的发送和接收
3. **NAT 穿透**: 通过 STUN/TURN 服务器支持复杂网络环境
4. **模块化**: Handler 架构易于扩展和定制
5. **跨平台**: 浏览器原生支持，无需插件

## 注意事项

1. **HTTPS 要求**: WebRTC 在生产环境必须使用 HTTPS
2. **TURN 服务器**: 公网部署需要配置 TURN 服务器
3. **浏览器兼容性**: 需要现代浏览器（Chrome 60+, Firefox 60+）
4. **带宽要求**: 音视频流需要稳定的网络连接
5. **并发限制**: 根据服务器性能配置 `concurrent_limit`

## 总结

OpenAvatarChat 通过 **WebRTC** 实现前后端的实时音视频通信，通过 **FastAPI** 提供 HTTP API 服务，通过 **Handler Pipeline** 处理音视频数据流。这种架构既保证了实时性，又保持了良好的可扩展性。
