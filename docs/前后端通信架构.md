# OpenAvatarChat 前后端通信架构（前后端分离版）

## 1. 文档目标

本文档描述当前项目的**实际通信方式**，核心原则是：

1. **严格沿用原项目端到端通信链路**（`/openavatarchat/initconfig`、`/webrtc/offer`、`/ws/*`）
2. **仅调整调用方式**（前后端分离后，前端通过 Vite 代理调用后端）
3. 后端不再承担前端静态资源托管，根路径 `/` 不再重定向页面

---

## 2. 当前总体架构

```
┌───────────────────────────────────────────────────────────────┐
│ 前端（独立进程）                                               │
│ 目录: frontend/                                                │
│ 启动: pnpm dev (默认 http://localhost:5173)                   │
│                                                               │
│ Vue3 + TS + WebRTC API                                        │
│   ├─ GET /openavatarchat/initconfig (经 Vite 代理)            │
│   ├─ POST /webrtc/offer (经 Vite 代理)                         │
│   └─ WebSocket /ws/* (经 Vite 代理)                           │
└───────────────────────────────────────────────────────────────┘
                              │
                              │ HTTP/WebSocket 代理转发
                              ▼
┌───────────────────────────────────────────────────────────────┐
│ 后端（独立进程）                                               │
│ 启动: .venv\Scripts\python.exe src/demo.py --config ...       │
│                                                               │
│ FastAPI + fastrtc + ChatEngine                                │
│   ├─ /openavatarchat/initconfig  配置接口（兼容旧路径）         │
│   ├─ /api/config               新配置接口（前后端分离友好）     │
│   ├─ /webrtc/offer             WebRTC 信令                     │
│   ├─ /ws/*                     LAM 等实时数据通道              │
│   └─ /                         默认 404（不再提供页面）         │
└───────────────────────────────────────────────────────────────┘
```

## 3. 关键变化（相对旧方案）

### 3.1 不变（必须保持）

- WebRTC 信令与媒体传输机制不变
- 前端核心调用路径不变：
  - `GET /openavatarchat/initconfig`
  - `POST /webrtc/offer`
  - `/ws/*`（如 LAM motion data）

### 3.2 已改变（调用方式变化）

- 前端从 `src/handlers/client/rtc_client/frontend/` 迁至根目录 `frontend/`
- 后端不再挂载 `/ui` 静态站点，也不再提供 `/gradio`
- 前端开发环境通过 `vite.config.ts` 代理后端

## 4. 后端接口说明（当前有效）

### 4.1 配置接口

#### 兼容旧路径（推荐保留）
- `GET /openavatarchat/initconfig`
- 用于前端初始化 WebRTC 配置和数字人配置

#### 新路径
- `GET /api/config`
- 与上面返回一致，便于新代码按 API 命名组织

返回示例：

```json
{
  "avatar_config": {
    "avatar_type": "lam",
    "avatar_ws_route": "/ws/lam_data_stream",
    "avatar_assets_path": "/download/lam_asset/james.zip"
  },
  "rtc_configuration": {
    "iceServers": [
      {
        "urls": "turn:...",
        "username": "...",
        "credential": "..."
      }
    ]
  }
}
```

### 4.2 WebRTC 信令接口

- `POST /webrtc/offer`
- 用于 offer/answer 与 ICE candidate 交换（由 fastrtc 挂载）

### 4.3 LAM 相关接口

- `GET /download/lam_asset/{file_name}`：获取 LAM 资产
- `WS /ws/lam_data_stream/{rtc_id}`：推送动作/音频相关数据

### 4.4 根路径说明

- `GET /` 返回 `404 {"detail":"Not Found"}` 是**预期行为**
- 不能把根路径 404 误判为“前后端未连通”

## 5. 前端调用与代理配置

### 5.1 前端调用方式（不变）

前端仍按原方式调用：

- `fetch('/openavatarchat/initconfig')`
- `fetch('/webrtc/offer', { method: 'POST', ... })`
- `new WebSocket('/ws/...')`

### 5.2 代理配置（关键）

`frontend/vite.config.ts` 需要确保代理到**后端实际端口**：

- 默认：`VITE_BACKEND_PORT || 8282`
- 代理路径：`/openavatarchat`、`/webrtc`、`/ws`、`/api`、`/download`

若后端不是 8282，需设置环境变量：

```bash
# Windows PowerShell
$env:VITE_BACKEND_PORT="8000"
pnpm dev
```

```

    │<═══════════════════════════════════════════════>│
```

## 8. 常见故障与判定标准

### 8.1 访问服务显示 `{"detail":"Not Found"}`

排查结论：
- 如果访问的是 `http://host:port/`，这是正常（根路由未定义）

正确验证方式：
- `GET /openavatarchat/initconfig` 应返回 200
- `GET /api/config` 应返回 200

### 8.2 前端页面可开，但无法建立 WebRTC

优先检查：
1. 前端代理端口是否与后端一致（例如后端 8282）
2. 浏览器是否允许麦克风/摄像头权限
3. TURN 配置是否正确（公网场景必须）
4. 后端日志是否出现 `/webrtc/offer` 请求

### 8.3 LAM 模式启动时报 `on_setup_app` 参数错误

原因：
- 前后端分离后，客户端 handler 的 `on_setup_app` 签名改为仅接收 `app`

处理原则：
- 不改通信路径，只把 handler 初始化调用方式适配到新签名

---

## 10. 结论

当前方案是：

- **通信链路严格沿用原项目端到端方式**（WebRTC + 既有接口路径）
- **仅改变调用组织方式**（前后端分离、前端代理后端）
- 根路径 404 是设计结果，不是连接失败

判断“是否连通”的标准应改为：

1. `/openavatarchat/initconfig` 返回 200
2. 前端发起 `/webrtc/offer` 请求并在后端日志可见
3. 建立 PeerConnection 后有上下行音视频流
